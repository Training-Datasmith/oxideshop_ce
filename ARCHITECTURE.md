# Architecture: oxideshop_ce (OXID eShop Community Edition)

## Purpose

OXID eShop Community Edition is a full-featured PHP e-commerce platform. It provides product catalog, shopping cart, checkout, payment integration, order management, CMS content, user accounts, promotions, and a back-office administration panel.

## Directory Structure

```
source/
  Application/
    Model/                     — Domain models (Active Record): Article, Basket, Order, User, etc.
    Controller/                — Frontend controllers: one per page type (ArticleDetails, Cart, etc.)
    Controller/Admin/          — Back-office controllers
    Component/                 — Reusable view components (user, basket, locator)
    views/                     — Smarty templates for frontend and admin
  Core/
    Exception/                 — Domain exceptions
    Model/                     — Base model classes (oxBase, oxList)
    Contract/                  — Interfaces for DI (IViewConfig, ISeoEncoder, etc.)
    ...
  modules/                     — Installed third-party modules
bootstrap.php                  — Application bootstrap
```

## Key Design Decisions

- **Active Record**: Domain models inherit from `oxBase` and know their own table name; they load, save, and delete themselves via `oxDb`
- **Unified namespace**: Models are accessed via `OxidEsales\Eshop\Application\Model\*` (generated by `oxideshop-unified-namespace-generator`); the actual class may be Community, Professional, or Enterprise edition
- **Module chain**: OXID's module system uses PHP class inheritance chains — a module extends the core class, and another module can extend the module. The chain is configured in `modules/` metadata
- **Smarty templating**: Frontend views use Smarty 3; the admin panel uses Smarty 2. Smarty plugins extend the template system
- **SEO URLs**: The `SeoEncoder*` classes generate and cache SEO-friendly URLs for all object types

## Extension Points

- Create a module in `source/modules/{vendor}/{module}/` with `metadata.php` to extend models, controllers, or templates
- Add event subscribers via `services.yaml` for Symfony-style DI in newer OXID versions

## Dependency Flow

```
HTTP request
  → bootstrap.php (front controller)
  → oxConfig (shop settings, multi-shop)
  → oxShopControl (routes to controller by cl= parameter)
  → Controller (loads Models, assigns to Smarty)
  → Smarty template → HTML response
```
